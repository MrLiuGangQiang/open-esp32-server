01 / AI HUB

AI 是连接枢纽，设备与应用系统围绕它协同

AI 不是三层结构中的中间层，而是统一接收设备输入、读取应用配置、做出决策并调度工具的核心连接点。

DEVICE输入 / 输出端

设备

AI 的感知器，也是 AI 的执行器

设备把现实世界变成 AI 可理解的输入，也把 AI 的决策变成可见、可听、可执行的结果。

麦克风、摄像头与扬声器，提供语音、视觉和表达通道
唤醒、VAD、流式播放与随时打断，形成自然交互
GPIO、红外与 OTA，把 AI 决策落到真实设备
对 AI 的价值：提供输入与输出边界，让智能真正到达用户。

调用记忆

配置 / 权限⇄状态 / 轨迹
APPLICATION SYSTEM配置 / 治理端

应用系统

AI 的配置面，也是 AI 的治理面

应用系统不替代 AI 决策，而是定义 AI 能看到什么、记住什么、调用什么，以及如何发布和运营。

配置角色、模型、知识、记忆和工具权限
绑定设备与用户，管理版本、参数和发布
记录对话、工具轨迹与运行状态，形成治理闭环
对 AI 的价值：提供规则、能力边界与可运营的上下文。
设备 → AI语音、图像与设备事件
应用 → AI角色、知识、模型与工具权限
AI → 设备回应、控制与任务执行
AI → 应用对话、工具轨迹与运行状态

02 / APPLICATION SYSTEM

应用系统，是 AI Hub 的低代码配置与治理面

manager-web、manager-mobile 与 manager-api 把 AI Hub 需要的角色、模型、设备、知识、MCP 与权限，组织成可视化配置。

智控台把 AI Hub 需要的一切，变成可配置、可复用、可发布的模块。

从角色与模型，到设备、知识库、MCP 工具与语音能力，项目已有能力都通过管理后台进入运行时，而不是每次重新开发。

01智能体管理角色配置、能力配置、MCP 授权、默认角色与快速模板。
02模型配置VAD、ASR、LLM、VLLM、Intent、TTS、Memory 可插拔选择。
03设备管理ESP32 设备、绑定关系、OTA、通讯录与设备互联。
04知识与记忆RAGFlow 知识库，以及 mem0ai、PowerMem、本地记忆方案。
05语音与身份声音克隆、声纹识别、替换词与语音资源管理。
06运营与治理用户、参数、字典、功能开关、对话记录与工具轨迹。
配置如何进入 AI Hub
CONFIGURE → SERVE → RUN → OBSERVE
01
前台配置管理员在 manager-web 或 manager-mobile 中完成智能体与能力配置。
02
接口与管理manager-api 负责用户、设备、模型、MCP、知识库与配置数据。
03
运行与反馈xiaofan-server 加载配置，AI Hub 执行会话，记录回传应用系统。
项目闭环 应用系统负责“配置与治理”，AI Hub 负责“理解、决策与调度”。

04 / RUNTIME FLOW

一次语音交互，AI Hub 在中心完成理解、决策与调度

设备输入通过 WebSocket 或 MQTT+UDP 进入 xiaofan-server；应用系统提供角色、模型、工具与知识配置；AI Hub 在运行时完成整条链路。

DV
ESP32 / ESP-SR设备唤醒

端侧检测唤醒词，开始采集语音，不需要持续上传音频。

NW
WEBSOCKET / MQTT+UDP音频上行

Opus 音频与设备事件进入 xiaofan-server，支持不同网络与部署形态。

AI
AI HUB / SPEECHVAD 与 ASR

运行时判断说话边界并流式识别，把语音转换成可理解的文本。

AP
MANAGER-API / CONTEXT加载应用配置

当前智能体的角色、模型、知识、MCP 工具与权限进入会话上下文。

AI
AI HUB / DECIDE意图、记忆与决策

Intent、LLM、Memory 与 RAG 协同判断：直接回答，还是调用工具完成任务。

TL
MCP / IOT / TTS执行与表达

MCP 工具或设备控制执行动作，TTS 流式返回语音，结果同步到对话记录。

项目示例：把客厅灯调暗ONE REAL PROJECT FLOW

→
AI Hub识别意图并决策
→
MCP / HA调用设备工具
→
设备执行并语音反馈
